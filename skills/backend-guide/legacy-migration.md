# Перенос старого кода в доменную структуру

Подход — постепенная замена (strangler fig), не переписывание. Главная
ловушка — продолжать писать новое в старый код (LEG-01).

## Подготовка (один раз)

1. Инвентаризация: домены, их возможности, таблицы и владелец каждой колонки.
2. Граф зависимостей доменов → порядок переноса: от листьев к центру. Домен,
   от которого зависят все (пользователь), — рано; домен, который зависит от
   всех (заказы/оплата), — поздно.
3. Инфраструктура: mypy, контейнер DI, миграции, import-linter с контрактом
   `legacy-boundary` (новый код не импортирует старые модули, кроме
   перечисленных исключений).
4. Пилот — маленький домен без денег. На нём отрабатывается шаблон; шаблон
   обновляется по итогам.

## Перенос одного домена

1. **Спецификация текущего поведения**: тексты дословно, кнопки, коды
   ответов, порядок шагов.
2. **Тесты против старого кода** — отдельный коммит без изменений в `src/`
   (LEG-02). Каждую ветку проверить порчей старого кода (TST-04). Операции над
   многими таблицами — тест-снимок: эталон снимается на старом коде.
3. **Перенос**: domain → application → adapters → ioc → controllers → удаление старого.
4. **Проверки**: контракты import-linter нового домена (с пробным нарушением), mypy strict.
5. Те же тесты зелёные без изменений → слияние → выкатка (LEG-06).
6. Обновить шаблон и `AGENTS.md`/`CLAUDE.md`, если что-то изменилось.

Найденный баг — отдельным изменением до или после переноса (LEG-03).
Изменение поведения, без которого перенос невозможен, — показать
владельцу, записать, тест — `xfail(strict=True)` до переноса (TST-06).

## Связь со старым кодом

| Ситуация | Решение |
|---|---|
| Новому нужно правило/данные старого | порт + `adapters/legacy_<что>.py` (LEG-04). При переносе соседа меняется только адаптер |
| Старый код вызывает перенесённое | метод старого модуля → однострочная обёртка над функцией домена (LEG-05) |
| Старый код ещё пишет таблицу домена | известное исключение в design/AGENTS.md, закрывается при переносе соседа |
| Новый код вынужден импортировать старый | `ignore_imports` в `legacy-boundary` с комментарием «зачем и когда снимется» |
| Один вариант команды/маршрута переносится, остальные — нет | обработчик домена с фильтром ровно на свой вариант — раньше старого |
| Порядок обработчиков важен (роутеры бота) | выписать соседние обработчики до переноса, сохранить порядок, тест на каждое пересечение |

Число исключений в `ignore_imports` — метрика долга: только уменьшается.
Последние исключения самые запутанные — их не откладывать до конца.
