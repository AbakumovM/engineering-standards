# asyncpg и чистый SQL (отклонение от DB-01 по умолчанию)

Записать в проекте: `- DB-01: asyncpg и чистый SQL вместо SQLAlchemy`.

- Пул создаётся один раз с `timeout` (соединение) и `command_timeout` (запрос) (ADP-01).
- Единица работы: соединение из пула + `transaction()` при первом обращении; `commit()`/
  `rollback()` сразу возвращают соединение. Gateway каждый раз просит `await uow.connection()`.
- View читает через `pool.fetch*` напрямую, соединение не держит (TX-05).
- Ожидаемый конфликт: `async with conn.transaction():` внутри открытой транзакции — это
  savepoint; `UniqueViolationError` → доменное исключение (TX-07).
- Нет `asyncio.gather` по одному соединению (TX-06).
- SQL, который зовут и старый, и новый код, — функциями от соединения в `adapters/sql.py`.
- Правило соседа для массового SQL — построитель условия из его `public.py`, передаётся
  параметром (DEP-05).
- Advisory lock — транзакционный (`pg_advisory_xact_lock`): сессионный может остаться
  захваченным на соединении, вернувшемся в пул.
