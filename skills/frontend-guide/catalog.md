# Каталог правил фронтенда

Группы: FSTR, FDEP — структура и границы; FCMP, FSTATE, FAPI, FFORM, FRTE —
компоненты, состояние, данные, формы, маршруты; FSEC, FPERF, FA11Y, FOBS —
безопасность, скорость, доступность, ошибки; FTST, FTS, FLEG — тесты, типы,
перенос старого кода.

Единый источник правил. Руководство (`frontend-guide`), ревью
(`frontend-review`) и проекты ссылаются на правила по номеру. Префикс `F`
отличает их от правил бэкенда (`backend-guide/catalog.md`).

## Как читать

- **Уровень.** `обязательно` — нарушение = дефект. `по умолчанию` — разумный
  выбор; проект может отступить, записав отклонение.
- **Почему** — что ломается без правила.
- **Проверка.** `авто` — линтер, компилятор или `fe_check.py`; `вручную` — на
  что смотреть при ревью.
- **Исключение** — когда отступить допустимо.

Отклонения — в `AGENTS.md` / `CLAUDE.md` проекта, раздел «Отклонения от общих
правил»: `- FSTATE-01: <где и почему>`. В коде —
`// arch-ignore[FSEC-01]: причина` на строке или строкой выше.

## FSTR — структура

### FSTR-01. Сначала фичи, внутри — слои
**Уровень:** по умолчанию.
Верх `src/`: `app/`, `routes/`, `features/`, `shared/`. Фича — часть продукта
с понятным пользователю смыслом (`assets`, `billing`, `auth`); внутри —
`api/`, `model/`, `ui/`, `index.ts`.
**Почему:** код одной задачи лежит рядом; фичу можно прочитать, поменять и
удалить целиком. Раскладка по типам (`components/`, `hooks/`, `services/`)
на сотне файлов превращается в поиск по всему проекту.
**Проверка:** авто — `fe_check.py` (каталоги верхнего уровня).
**Исключение:** проект уже на Feature-Sliced Design (`entities/`, `widgets/`,
`pages/`) — оставить FSD, записать отклонение, границы проверять Steiger.

### FSTR-02. Слой появляется вместе с кодом
**Уровень:** обязательно.
Нет пустых `model/`, `index.ts` без экспортов, `types.ts` «на будущее».
Маленькой фиче достаточно `ui/` и `index.ts`.
**Почему:** пустые каталоги — шум для людей и агентов, создают ложное
ожидание, что там что-то есть.
**Проверка:** авто — `fe_check.py` (пустые файлы).
**Исключение:** нет.

### FSTR-03. Нет свалок
**Уровень:** обязательно.
Нет `utils/`, `helpers/`, `common/`, `misc/`, верхнеуровневых `components/`,
`hooks/`. Общая техника — `shared/lib/<назначение>/` (`format/`, `dates/`),
общие компоненты — `shared/ui/`.
**Почему:** свалка растёт без владельца, в неё попадает код фич, и границы
перестают значить что-либо.
**Проверка:** авто — `fe_check.py`.
**Исключение:** `shared/lib/utils.ts` с функцией `cn` — так его ждёт shadcn/ui.

### FSTR-04. SPA на Vite по умолчанию
**Уровень:** по умолчанию.
Приложение за логином (кабинет, админка, внутренний сервис) — SPA на Vite,
бэкенд отдельно. SSR/SSG — когда нужны SEO, быстрый первый показ публичных
страниц или серверный код рядом с UI: тогда Next.js (или TanStack Start), это
отклонение.
**Почему:** SPA проще развернуть (статика), проще отлаживать, нет второго
сервера с секретами и своей безопасностью. Сложность SSR оправдана, только
когда нужна.
**Проверка:** вручную.
**Исключение:** публичный сайт, лендинг, контентные страницы.

### FSTR-05. Файл маршрута тонкий
**Уровень:** обязательно.
Маршрут: проверить параметры (`validateSearch`), загрузить данные
(`loader`), собрать страницу из компонентов фич. Нет условий бизнес-смысла,
нет разметки длиннее экрана.
**Почему:** маршрут — аналог контроллера; логика в нём не переиспользуется
и не тестируется.
**Проверка:** вручную; авто — `fe_check.py` (длина файла маршрута).
**Исключение:** нет.

## FDEP — зависимости

### FDEP-01. Направление вниз
**Уровень:** обязательно.
`app` → `routes` → `features` → `shared`. Нижний слой не импортирует верхний.
**Почему:** циклы и обратные зависимости делают невозможным менять код по
частям; `shared`, знающий о фиче, тянет её во все сборки.
**Проверка:** авто — ESLint `boundaries/element-types`, `fe_check.py`.
**Исключение:** нет.

### FDEP-02. `shared` не знает о фичах
**Уровень:** обязательно.
`shared/ui` — компоненты без бизнес-смысла (`Button`, `DataTable`), данные
получает пропсами. Компонент, знающий об «активе» или «оплате», — в фиче.
**Почему:** иначе `shared` превращается в свалку (FSTR-03).
**Проверка:** авто — ESLint boundaries, `fe_check.py`.
**Исключение:** нет.

### FDEP-03. Чужая фича — только через `index.ts`
**Уровень:** обязательно.
`import { AssetBadge } from "@/features/assets"`, не
`"@/features/assets/ui/AssetBadge"`. `index.ts` экспортирует только то, что
нужно соседям.
**Почему:** внутренности фичи можно менять, не ломая соседей; публичная
поверхность видна в одном файле.
**Проверка:** авто — ESLint `boundaries/entry-point`, `fe_check.py`.
**Исключение:** нет.

### FDEP-04. Фичи компонуются в маршруте
**Уровень:** по умолчанию.
Страница «заказ с данными клиента» собирается в маршруте из компонентов двух
фич, а не импортом одной фичи в другую. Импорт фича → фича — редкость, без
циклов.
**Почему:** граф фич остаётся деревом; фичу можно удалить, не трогая соседей.
**Проверка:** авто — `fe_check.py` (предупреждение на импорт фича → фича;
ошибка на цикл).
**Исключение:** небольшая фича-сущность (`users`) используется многими —
допустимо через `index.ts`.

### FDEP-05. Границы проверяет линтер в CI
**Уровень:** обязательно.
`eslint-plugin-boundaries` настроен (шаблон —
`templates/frontend/eslint.config.js`), `pnpm lint` в CI.
**Почему:** границы без проверки исчезают за месяц.
**Проверка:** авто — наличие конфигурации; `fe_check.py`.
**Исключение:** нет.

## FCMP — компоненты

### FCMP-01. Компонент отображает, правило — в `model/`
**Уровень:** обязательно.
«Можно ли отменить», «сколько к оплате», «какой статус показать» — чистая
функция в `features/<фича>/model/` с тестом. Компонент её вызывает.
Решение, меняющее данные (доступ, цена, лимит), принимает сервер; фронт
только отображает (FFORM-03, FSEC-07).
**Почему:** условие в JSX не тестируется без рендера, дублируется по
компонентам и расходится.
**Проверка:** вручную.
**Исключение:** тривиальные условия отображения (`isLoading`, пустой список).

### FCMP-02. Нет загрузки данных в компоненте
**Уровень:** обязательно.
Нет `fetch`, `axios`, вызова SDK в теле компонента или `useEffect`. Данные —
`useQuery`/`useSuspenseQuery` с options из `api/` фичи или `loader` маршрута.
**Почему:** самописная загрузка теряет кэш, отмену, повторы, состояние
ошибки; гонки при быстрой смене параметров.
**Проверка:** авто — `fe_check.py`.
**Исключение:** нет.

### FCMP-03. `useEffect` — только синхронизация с внешним миром
**Уровень:** обязательно.
`useEffect` — подписка, таймер, сторонняя библиотека, DOM-API. Не для:
вычисления производного значения (считать при рендере), реакции на событие
(делать в обработчике), сброса состояния при смене пропса (`key`).
**Почему:** лишние рендеры, рассинхронизация, бесконечные циклы. См.
react.dev «You Might Not Need an Effect».
**Проверка:** вручную; авто — `react-hooks` (exhaustive-deps, правила компилятора).
**Исключение:** нет.

### FCMP-04. Стабильный ключ списка
**Уровень:** обязательно.
`key={item.id}`, не `key={index}`.
**Почему:** при вставке и сортировке React переиспользует не тот элемент:
теряется ввод, путается состояние.
**Проверка:** авто — `fe_check.py`.
**Исключение:** статичный список, который никогда не меняется.

### FCMP-05. Компонент — одна задача
**Уровень:** по умолчанию.
Больше ~200 строк или больше 3–4 независимых состояний — разделить. Пропсы —
явный тип; без «пробрасывания» через 3+ уровня (компоновка через `children`,
контекст, стор).
**Почему:** большой компонент перерисовывается целиком и не читается.
**Проверка:** авто — `fe_check.py` (длина файла, предупреждение).
**Исключение:** таблицы-конфигурации колонок, формы с большим числом полей;
компоненты shadcn/ui в `shared/ui` (сторонний код, скрипт их не проверяет).

### FCMP-06. Ручная мемоизация — по замеру
**Уровень:** по умолчанию.
Включён React Compiler. `useMemo`, `useCallback`, `memo` — только когда
Profiler показал проблему или нужна стабильная ссылка для внешней
библиотеки. Существующие не удалять массово.
**Почему:** компилятор мемоизирует сам; ручная мемоизация — шум и источник
ошибок в зависимостях.
**Проверка:** вручную.
**Исключение:** проект без компилятора — записать отклонение.

## FSTATE — состояние

### FSTATE-01. Данные сервера — только в TanStack Query
**Уровень:** обязательно.
Не копировать ответ в `useState`, Zustand, контекст. Нужно преобразовать —
`select` в options или вычислить при рендере.
**Почему:** копия устаревает: после мутации кэш обновился, копия — нет.
**Проверка:** вручную; авто — `fe_check.py` (`setX(data)` в `useEffect`).
**Исключение:** черновик формы, начальное значение которого — с сервера
(`defaultValues`).

### FSTATE-02. Состояние, которым делятся, — в URL
**Уровень:** обязательно.
Фильтры, сортировка, курсор/страница, открытая вкладка, id открытой карточки
— search params маршрута, проверенные схемой (`validateSearch`).
**Почему:** ссылку можно отправить, кнопка «назад» работает, перезагрузка
не теряет состояние.
**Проверка:** вручную.
**Исключение:** временное состояние (открыт ли выпадающий список).

### FSTATE-03. Локальное — рядом, общее — маленький стор
**Уровень:** по умолчанию.
`useState` в компоненте, которому нужно. Общее клиентское состояние нескольких
страниц (корзина, черновик мастера) — стор Zustand в `model/` фичи, один стор
на задачу. Глобального «стора приложения» нет.
**Почему:** глобальный стор становится вторым бэкендом без схемы и тестов.
**Проверка:** вручную.
**Исключение:** нет.

### FSTATE-04. Контекст — для редко меняющегося
**Уровень:** по умолчанию.
Тема, язык, текущий пользователь, настройки. Часто меняющееся значение в
контексте перерисовывает всё дерево.
**Почему:** производительность и непредсказуемые перерисовки.
**Проверка:** вручную.
**Исключение:** нет.

### FSTATE-05. Одно значение — один источник
**Уровень:** обязательно.
Не хранить то, что вычисляется (`fullName` при наличии `first`/`last`,
`total` при наличии позиций). Не держать одно и то же в URL и в `useState`.
**Почему:** два источника расходятся.
**Проверка:** вручную.
**Исключение:** нет.

## FAPI — данные и API

### FAPI-01. Клиент генерируется из OpenAPI
**Уровень:** обязательно.
`@hey-api/openapi-ts` генерирует типы, SDK, Zod-схемы и options TanStack
Query в `shared/api/generated/`. Каталог не правится руками; генерация — по
команде `pnpm api:generate`; в CI сверяется, что сгенерированное совпадает со
схемой бэкенда.
**Почему:** ручные типы ответов расходятся с бэкендом молча; генерация делает
несовместимость ошибкой компиляции.
**Проверка:** авто — `fe_check.py` (ручные `interface ...Response`,
правки в `generated/` через `git diff`).
**Исключение:** внешний API без OpenAPI — схема Zod на границе (FTS-04).

### FAPI-02. Запросы — только через клиент из `shared/api`
**Уровень:** обязательно.
Базовый URL, заголовки (`X-Request-ID`, CSRF), таймаут, разбор ошибок —
настроены один раз в `shared/api/client.ts`. Фичи используют
сгенерированные функции и options.
**Почему:** иначе у каждого запроса свои заголовки, таймауты и обработка
ошибок.
**Проверка:** авто — `fe_check.py` (`fetch(`, `axios` вне `shared/api`).
**Исключение:** загрузка статических файлов, `sendBeacon` метрик.

### FAPI-03. Ключи запросов и инвалидация
**Уровень:** обязательно.
Ключи — сгенерированные или из фабрики `assetQueries` в `api/` фичи. После
мутации — `invalidateQueries` по нужным ключам (или `setQueryData` из ответа);
не `window.location.reload()`, не «перезапросить всё».
**Почему:** ручные строковые ключи расходятся, данные на экране устаревают.
**Проверка:** вручную; авто — `fe_check.py` (`location.reload`).
**Исключение:** нет.

### FAPI-04. Одна обработка ошибок
**Уровень:** обязательно.
Ответ `application/problem+json` (RFC 9457) превращается в `ApiError`
(`status`, `type`, `title`, `detail`, `errors`, `requestId`) в одном месте.
`401` — на вход; `403`/`404` — экран «нет доступа/не найдено»; `409` —
сообщение о конфликте и обновление данных; `422` — ошибки у полей формы;
`429`/`503` — «попробуйте позже» с учётом `Retry-After`; `5xx` — общий экран
с `request_id`.
**Почему:** иначе каждый компонент показывает ошибку по-своему или никак.
**Проверка:** вручную.
**Исключение:** нет.

### FAPI-05. Списки — курсором
**Уровень:** обязательно.
`useInfiniteQuery` с `getNextPageParam` из ответа бэкенда (`next_cursor`),
кнопка «ещё» или бесконечная прокрутка. Нет запросов «все записи».
**Почему:** список растёт; «всё сразу» убивает и сервер, и браузер.
**Проверка:** вручную.
**Исключение:** справочник с потолком (≤ 100 элементов), так и в API.

### FAPI-06. Создание и оплата — без дублей
**Уровень:** обязательно.
Мутация, создающая объект или списывающая деньги: `Idempotency-Key`
(`crypto.randomUUID()`), созданный один раз на попытку пользователя и
переиспользуемый при повторной отправке той же формы; кнопка заблокирована,
пока запрос идёт (`isPending`).
**Почему:** двойной клик, медленная сеть и повтор после таймаута создают два
заказа.
**Проверка:** вручную.
**Исключение:** бэкенд гарантирует уникальность иначе (естественный ключ).

### FAPI-07. Повторы — только чтение
**Уровень:** обязательно.
Запросы: `retry` не для `4xx` (кроме `408`/`429`), не больше 2–3 раз.
Мутации: `retry: 0` (повтор — решение пользователя или ключ идемпотентности).
**Почему:** повтор неидемпотентного действия = дубль; повтор `4xx`
бессмыслен.
**Проверка:** вручную — настройки `QueryClient`.
**Исключение:** мутация с `Idempotency-Key` — повтор допустим.

### FAPI-08. `staleTime` и отмена
**Уровень:** по умолчанию.
Глобальный `staleTime` (например, 30 с) вместо `0`; для справочников —
больше. `signal` из контекста запроса передаётся в клиент — запрос отменяется
при уходе со страницы.
**Почему:** при `staleTime: 0` каждый фокус окна и монтирование —
перезапрос: лишняя нагрузка на бэкенд.
**Проверка:** вручную.
**Исключение:** данные, которые обязаны быть свежими (баланс) — короче.

## FFORM — формы

### FFORM-01. Схема Zod — источник типа формы
**Уровень:** обязательно.
`createAssetSchema` в `model/`; тип — `z.infer<typeof createAssetSchema>`.
Схема переиспользует сгенерированную из OpenAPI, где совпадает.
**Почему:** тип и проверка не расходятся.
**Проверка:** вручную.
**Исключение:** форма из одного поля без правил.

### FFORM-02. react-hook-form + `zodResolver`
**Уровень:** по умолчанию.
Компоненты формы — `shared/ui/form` (shadcn/ui Form): `label`, сообщение
об ошибке и `aria-describedby` связаны автоматически.
**Почему:** неуправляемые поля, мало перерисовок, единая доступность.
**Проверка:** вручную.
**Исключение:** проект на TanStack Form — отклонение.

### FFORM-03. Сервер — источник истины
**Уровень:** обязательно.
Клиентская проверка — для удобства. Ошибки `422` от сервера показываются у
полей (`setError`), неизвестные — общим сообщением формы.
**Почему:** клиентскую проверку обходят; правила на сервере меняются раньше.
**Проверка:** вручную.
**Исключение:** нет.

### FFORM-04. Отправка — один раз
**Уровень:** обязательно.
Кнопка заблокирована и показывает состояние, пока идёт отправка; повторная
отправка той же формы — с тем же `Idempotency-Key` (FAPI-06).
**Почему:** двойная отправка.
**Проверка:** вручную.
**Исключение:** нет.

## FRTE — маршруты

### FRTE-01. Search params проверены схемой
**Уровень:** обязательно.
`validateSearch` со схемой Zod, значения по умолчанию в схеме; неверные
параметры не роняют страницу.
**Почему:** URL — ввод пользователя.
**Проверка:** вручную.
**Исключение:** нет.

### FRTE-02. Данные маршрута — `loader` + кэш Query
**Уровень:** по умолчанию.
`loader: ({ context }) => context.queryClient.ensureQueryData(assetQueries.detail(id))`,
в компоненте — `useSuspenseQuery` с теми же options. Загрузка начинается при
переходе (и при наведении на ссылку — `preload: "intent"`), без каскадов
«компонент смонтировался → запрос».
**Почему:** каскады запросов — основная причина медленных SPA.
**Проверка:** вручную.
**Исключение:** второстепенные данные страницы — `useQuery` в компоненте.

### FRTE-03. Защита маршрута — удобство
**Уровень:** обязательно.
`beforeLoad` перенаправляет неавторизованного на вход; права на данные
проверяет бэкенд (FSEC-07).
**Почему:** код фронта виден и изменяем пользователем.
**Проверка:** вручную.
**Исключение:** нет.

### FRTE-04. Маршруты — отдельные чанки
**Уровень:** обязательно.
`autoCodeSplitting: true` в плагине TanStack Router; тяжёлые редкие
компоненты (редактор, графики) — `lazy`.
**Почему:** первый экран не должен грузить код всего приложения.
**Проверка:** авто — `fe_check.py` (настройка плагина).
**Исключение:** нет.

### FRTE-05. Ошибки и «не найдено» на маршрутах
**Уровень:** обязательно.
У корня — `errorComponent` и `notFoundComponent`; у маршрутов с данными —
свои, если нужен особый текст.
**Почему:** белый экран вместо сообщения (FOBS-01).
**Проверка:** вручную.
**Исключение:** нет.

## FSEC — безопасность

Источники: OWASP Top 10, OWASP Cheat Sheets (XSS, HTML5 Security, CSP),
IETF «OAuth 2.0 for Browser-Based Applications» (BFF).

### FSEC-01. Нет HTML из данных без очистки
**Уровень:** обязательно.
JSX экранирует сам. `dangerouslySetInnerHTML`, `innerHTML`,
`insertAdjacentHTML`, `document.write` — только с `DOMPurify.sanitize(...)`
и только если без HTML нельзя. Markdown — рендерер без сырого HTML.
**Почему:** XSS — кража сессии, действия от имени пользователя.
**Проверка:** авто — `fe_check.py`, ESLint `react/no-danger`.
**Исключение:** HTML из собственного кода (не из данных) — с
`arch-ignore[FSEC-01]` и причиной.

### FSEC-02. Токены — не в хранилище браузера
**Уровень:** обязательно.
Сессия — cookie `HttpOnly; Secure; SameSite=Lax|Strict`, ставит бэкенд (или
BFF). Если access token неизбежен в браузере — только в памяти, короткий,
обновление — через HttpOnly-cookie. Нет токенов в `localStorage`,
`sessionStorage`, IndexedDB, URL.
**Почему:** любой скрипт на странице (XSS, скомпрометированная зависимость)
читает хранилище и уносит токен.
**Проверка:** авто — `fe_check.py`.
**Исключение:** нет.

### FSEC-03. CSRF при cookie-сессии
**Уровень:** обязательно.
Изменяющие запросы — не `GET`; клиент шлёт CSRF-заголовок (токен из cookie
или ответа), бэкенд проверяет его и `Origin`. `SameSite` — дополнительная
защита, не единственная.
**Почему:** cookie браузер отправляет сам, в том числе с чужого сайта.
**Проверка:** вручную — `shared/api/client.ts`.
**Исключение:** API с токеном в заголовке, без cookie.

### FSEC-04. В бандле нет секретов
**Уровень:** обязательно.
Всё с префиксом `VITE_` и всё в коде фронта — публично. Ключи платёжек,
токены ботов, пароли — только на сервере. Публичные ключи (Sentry DSN,
публичный ключ карт) — допустимы.
**Почему:** бандл скачивает любой.
**Проверка:** авто — `fe_check.py` (`VITE_*SECRET*`, `*TOKEN*`, `*PASSWORD*`,
`*PRIVATE*`; ключи в коде).
**Исключение:** нет.

### FSEC-05. CSP и заголовки
**Уровень:** по умолчанию.
Раздающий сервер (nginx/CDN) отдаёт `Content-Security-Policy` без
`unsafe-eval` и без `unsafe-inline` для скриптов,
`X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
`frame-ancestors 'none'` (или список), HSTS. Сначала —
`Content-Security-Policy-Report-Only`.
**Почему:** CSP ограничивает ущерб от XSS; `frame-ancestors` — от
кликджекинга.
**Проверка:** вручную — конфигурация раздачи.
**Исключение:** встраиваемый виджет — свой `frame-ancestors`.

### FSEC-06. Ссылки и редиректы из данных
**Уровень:** обязательно.
URL из данных или параметра (`?next=`) — проверить: схема `http:`/`https:`,
для редиректа — свой origin или белый список.
**Почему:** `javascript:` в `href` — XSS; открытый редирект — фишинг.
**Проверка:** вручную; авто — `fe_check.py` (`href={` с данными — подсказка).
**Исключение:** нет.

### FSEC-07. Права — на сервере
**Уровень:** обязательно.
Скрыть кнопку админа — удобство. Каждый запрос бэкенд проверяет сам
(`backend` SEC-01, SEC-02). Фронт не передаёт «роль» или «цену» как
источник истины.
**Почему:** запрос можно отправить в обход интерфейса.
**Проверка:** вручную.
**Исключение:** нет.

### FSEC-08. Зависимости — осознанно
**Уровень:** обязательно.
Lock-файл в репозитории, `pnpm install --frozen-lockfile` в CI; новая
зависимость — проверить поддержку, размер, число транзитивных;
`pnpm audit` в CI. Новые версии пакетов — не моложе нескольких дней
(`minimumReleaseAge` в pnpm); скрипты установки — только разрешённым пакетам.
**Почему:** атаки через цепочку поставок — основной путь компрометации
фронтенда.
**Проверка:** авто — lock-файл в репозитории, CI; вручную — новые пакеты.
**Исключение:** нет.

### FSEC-09. `postMessage` и встраивание
**Уровень:** обязательно.
Обработчик `message` проверяет `event.origin` по белому списку и форму
данных схемой; отправка — с явным `targetOrigin`, не `"*"`.
**Почему:** любое окно может прислать сообщение.
**Проверка:** авто — `fe_check.py`.
**Исключение:** нет.

### FSEC-10. Нет выполнения строк
**Уровень:** обязательно.
Нет `eval`, `new Function`, `setTimeout("строка")`.
**Почему:** выполнение данных как кода; ломает CSP.
**Проверка:** авто — `fe_check.py`, ESLint `no-eval`, `no-implied-eval`.
**Исключение:** нет.

### FSEC-11. Персональные данные — минимум
**Уровень:** обязательно.
Не класть в URL, `localStorage`, аналитику, сбор ошибок (`sendDefaultPii:
false`, маскирование в записи сессий). Выход из аккаунта очищает кэш Query и
сторы.
**Почему:** URL попадает в логи и `Referer`; хранилище переживает выход.
**Проверка:** вручную.
**Исключение:** нет.

## FPERF — скорость

Источники: web.dev (Core Web Vitals), react.dev, документация Vite.

### FPERF-01. Код делится по маршрутам
**Уровень:** обязательно. См. FRTE-04.

### FPERF-02. Бюджет бандла
**Уровень:** по умолчанию.
Бюджет задан в проекте (ориентир: JS первого экрана ≤ 200 КБ gzip) и
проверяется в CI (`size-limit` или проверка отчёта сборки).
**Почему:** бандл растёт по килобайту, незаметно, пока не станет медленным.

записать.

### FPERF-03. Core Web Vitals измеряются у пользователей
**Уровень:** по умолчанию.
Цели (75-й перцентиль): LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1. Библиотека
`web-vitals` отправляет значения в аналитику/сбор ошибок; Lighthouse —
только для отладки.
**Почему:** лабораторные замеры не видят медленные устройства и сети.
**Проверка:** вручную.
**Исключение:** нет.

### FPERF-04. Длинные списки
**Уровень:** обязательно.
Больше ~200 строк на экране — виртуализация (TanStack Virtual) или
пагинация (FAPI-05).
**Почему:** тысячи DOM-узлов — медленный рендер и ввод (INP).
**Проверка:** вручную.
**Исключение:** нет.

### FPERF-05. Изображения и шрифты
**Уровень:** по умолчанию.
У `<img>` — `width`/`height` (или `aspect-ratio`), `loading="lazy"` ниже
первого экрана, `fetchpriority="high"` у главного; форматы WebP/AVIF; шрифты
— `font-display: swap`, свои, а не с внешних CDN.
**Почему:** CLS и LCP.
**Проверка:** авто — `fe_check.py` (`<img>` без размеров — подсказка).
**Исключение:** нет.

### FPERF-06. Тяжёлые зависимости — после проверки
**Уровень:** по умолчанию.
Перед добавлением — размер (bundlephobia / отчёт сборки), есть ли tree
shaking. Нет `moment`, `lodash` целиком (`lodash-es` по функциям или
стандартная библиотека), `date-fns`/`Intl` для дат.
**Почему:** одна библиотека может удвоить бандл.
**Проверка:** авто — `fe_check.py` (известные тяжёлые импорты).
**Исключение:** нет.

### FPERF-07. Главный поток свободен
**Уровень:** по умолчанию.
Поиск по вводу — с задержкой (debounce) или `useDeferredValue`; тяжёлые
вычисления (разбор больших файлов) — Web Worker; обновления, которые могут
подождать, — `startTransition`.
**Почему:** INP: интерфейс отвечает на клик дольше 200 мс.
**Проверка:** вручную.
**Исключение:** нет.

## FOBS — ошибки и наблюдаемость

### FOBS-04. Нет отладочного вывода в проде

**Проверка:** авто — `fe_check.py`, ESLint.

### FOBS-05. `request_id` в сообщении об ошибке

Экран ошибки показывает `request_id` из problem+json/заголовка

**Почему:** по нему ошибку находят в логах бэкенда за секунды.
**Проверка:** вручную.
**Исключение:** нет.

### FOBS-06. Метрики пользователя
**Уровень:** по умолчанию.
Web Vitals (FPERF-03) и ключевые события (оплата прошла/не прошла) —

### FTS-04. Данные извне — через схему

**Проверка:** авто — `fe_check.py` (`JSON.parse(...) as`).
**Исключение:** нет.

### FTS-05. Без `enum`
**Уровень:** по умолчанию.
Объединение литералов или `as const`.
**Почему:** `enum` генерирует код, не работает в режиме «только стирание

**Проверка:** авто — `fe_check.py`.
**Исключение:** сгенерированный код.

## FLEG — перенос старого кода

### FLEG-01. Новое — в новой структуре
**Уровень:** обязательно.

**Уровень:** по умолчанию.
`allowJs`, новые файлы — только `.ts`/`.tsx`; при правке файл переводится.
**Почему:** большой перевод за раз не проходит ревью.
**Проверка:** авто — `fe_check.py` (новые `.js`/`.jsx` в diff).
**Исключение:** нет.

### FLEG-03. Сначала тест, перенос не меняет поведение
**Уровень:** обязательно.
Перед переносом — e2e или тест компонента на текущее поведение; перенос и
исправление бага — разные коммиты.
**Почему:** иначе непонятно, что сломал перенос.
**Проверка:** вручную.
**Исключение:** нет.

### FLEG-04. Смена сборщика или фреймворка — отдельная задача
**Уровень:** обязательно.
CRA/webpack → Vite, React Router → TanStack Router, Redux → Query + Zustand —
каждое отдельно, со своими тестами; не вместе с фичами.
**Почему:** смешанный дифф невозможно проверить.
**Проверка:** вручную.
**Исключение:** нет.
