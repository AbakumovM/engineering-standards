# Перенос старого фронтенда

Правила — `catalog.md`, группа FLEG. Перенос не меняет поведение; каждый
шаг — отдельный MR, который можно откатить.

## Порядок

1. **Записать состояние.** В `AGENTS.md` проекта: где старый код
   (`src/legacy/`, `src/components/`…), что уже перенесено, отклонения на
   время переноса (`- FTS-01: legacy/ без strict до переноса`).
2. **Страховка.** e2e на главные пути старого приложения (FLEG-03) — они
   проверяют каждый следующий шаг.
3. **Инструменты, без изменения кода.** TypeScript с `allowJs`, ESLint,
   Prettier, Vitest — для нового кода; старое — в `ignores`/мягкий режим.
4. **Сборщик** (если CRA/webpack) → Vite — отдельной задачей (FLEG-04):
   `index.html` в корень, `process.env.REACT_APP_*` → `import.meta.env.VITE_*`,
   SVG как компоненты — `vite-plugin-svgr`.
5. **Клиент API** — сгенерировать из OpenAPI; старые вызовы переводить по
   одному эндпоинту.
6. **Новое — в `features/`** с первого дня (FLEG-01). Старое переносится, когда
   его всё равно трогают: фича целиком, с тестами.
7. **Состояние сервера.** Redux/MobX-хранилища с данными API → TanStack
   Query по одному срезу; то, что осталось клиентским, — Zustand или
   `useState`.
8. **Роутер** — последним, когда страницы уже в новой структуре.

## Типичные замены

| Было | Стало |
|---|---|
| `useEffect` + `fetch` + `useState(loading)` | `useQuery(options)` |
| Redux-срез с данными API, thunks | Query + мутации с инвалидацией |
| `axios` с перехватчиками в каждом модуле | один клиент в `shared/api` |
| Ручные типы ответов | сгенерированные |
| Formik / ручные формы | react-hook-form + Zod |
| CSS-модули / styled-components | Tailwind в новом коде; старое не переписывать ради стиля |
| `moment` | `Intl` / `date-fns` |
| Токен в `localStorage` | cookie-сессия (нужна доработка бэкенда, FSEC-02) — приоритет |

## Проверки на время переноса

`fe_check.py --legacy src/legacy src/components` пропускает старое;
в режиме изменений (`--diff`) новые `.js`/`.jsx` — предупреждение (FLEG-02).
Граница «новое не импортирует старое» — правило `boundaries` для `legacy`.
