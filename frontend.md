# Фронтенд: веб-приложения на TypeScript и React

Номера (`FDEP-03`) ведут в `frontend-guide/catalog.md`: там причина, способ
проверки и исключения.

**`frontend-guide`** — перед тем как создать проект, фичу, маршрут, форму,
запрос к API, общий компонент, хранилище состояния или переносить старый
код. **`frontend-review`** — после фичи, перед коммитом/MR, по просьбе
«проверь фронт / код / безопасность / доступность».

## Стек по умолчанию

TypeScript strict, pnpm; React 19 + React Compiler; Vite 8 (SPA);
TanStack Router (маршруты в файлах) + TanStack Query 5 (данные сервера);
клиент API — `@hey-api/openapi-ts` из OpenAPI бэкенда; формы —
react-hook-form + Zod 4; UI — Tailwind CSS 4 + shadcn/ui; клиентское
состояние — Zustand (только если нужно); ESLint (typescript-eslint strict,
react-hooks, jsx-a11y, boundaries) + Prettier; knip; Vitest + Testing
Library + MSW; Playwright + axe; Sentry-совместимый сбор ошибок.
Публичный сайт с SEO/SSR — Next.js, записать отклонением (FSTR-04).

## Структура

```
src/
  app/              # сборка: провайдеры (QueryClient, роутер, тема), стили, корневые ошибки
  routes/           # маршруты: параметры, загрузка, компоновка фич — без бизнес-логики
  features/<фича>/
    api/            # запросы и мутации фичи поверх сгенерированного клиента
    model/          # правила отображения, схемы форм, хранилище — чистые функции с тестами
    ui/             # компоненты фичи
    index.ts        # единственное, что импортируют снаружи
  shared/
    api/            # generated/ (не править), настройка клиента, разбор ошибок
    ui/             # дизайн-система (shadcn/ui) — ничего не знает о фичах
    lib/<назначение>/  # техника: format/, dates/ — не свалка
    config/         # переменные окружения, проверенные схемой при старте
```

- Сначала фичи, внутри слои; слой появляется, когда в нём есть код (FSTR-01, FSTR-02).
- Нет `utils/`, `helpers/`, `common/`, `components/` на верхнем уровне (FSTR-03).
- Файл маршрута тонкий: параметры → загрузка → компоненты фич (FSTR-05).

## Главные правила

**Зависимости**
- Направлены вниз: `app` → `routes` → `features` → `shared` (FDEP-01).
- `shared` не импортирует фичи, маршруты, `app` (FDEP-02).
- Чужая фича — только через её `index.ts`; лучше компоновать в маршруте (FDEP-03, FDEP-04).
- Границы проверяет ESLint (boundaries) в CI (FDEP-05).

**Компоненты**
- Компонент отображает; правило («можно ли», статус, сумма) — чистая функция в `model/` (FCMP-01).
- Нет `fetch` и загрузки данных в `useEffect` (FCMP-02). `useEffect` — только
  синхронизация с внешним миром; производное вычисляется при рендере (FCMP-03).
- Ключ списка — стабильный id, не индекс (FCMP-04). Ручной `useMemo`/`memo` — по замеру (FCMP-06).

**Состояние**
- Данные сервера живут только в TanStack Query; не копировать в `useState`/стор (FSTATE-01).
- Фильтры, страница, вкладка — в URL, search params проверены схемой (FSTATE-02).
- Локальное — `useState` рядом; общее клиентское — маленький стор в фиче (FSTATE-03).

**API**
- Клиент генерируется из OpenAPI бэкенда, `generated/` не правится (FAPI-01).
- Запросы — только через клиент из `shared/api`; нет `fetch`/`axios` в фичах (FAPI-02).
- После мутации — инвалидация нужных ключей, а не перезагрузка страницы (FAPI-03).
- Ошибки problem+json разбираются в одном месте; `422` — ошибки у полей формы (FAPI-04).
- Список — курсор и `useInfiniteQuery`, не «всё сразу» (FAPI-05).
- Создающая/платёжная мутация — `Idempotency-Key` на попытку пользователя,
  кнопка заблокирована до ответа (FAPI-06).
- Повторяется только чтение; мутации и `4xx` не повторяются; `staleTime` задан (FAPI-07, FAPI-08).

**Формы и маршруты**
- Схема Zod в `model/`, типы из неё; react-hook-form + `zodResolver` (FFORM-01, FFORM-02).
- Проверка на клиенте — для удобства; источник истины — сервер (FFORM-03).
- Данные маршрута — `loader` + `ensureQueryData`; маршруты делятся на чанки (FRTE-02, FRTE-04).

**Безопасность**
- Нет `dangerouslySetInnerHTML` с чужими данными; нужен HTML — DOMPurify (FSEC-01).
- Токены не в `localStorage`/`sessionStorage`: сессия — HttpOnly-cookie,
  access token — только в памяти (FSEC-02).
- `VITE_*` попадает в бандл — секретов там нет (FSEC-04). CSP без `unsafe-eval` (FSEC-05).
- Ссылки из данных — только `http(s):` (FSEC-06). Нет `eval`, `new Function` (FSEC-10).

**Скорость и доступность**
- Core Web Vitals (p75): LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 — измеряются у пользователей (FPERF-03).
- Бюджет бандла задан и проверяется; тяжёлая зависимость — после проверки размера (FPERF-02, FPERF-06).
- Длинный список — виртуализация или пагинация (FPERF-04).
- Кнопка — `<button>`, ссылка — `<a>`/`Link`; нет `onClick` на `div` (FA11Y-01).
- Всё работает с клавиатуры, фокус виден; у полей `label`, у картинок `alt` (FA11Y-02, FA11Y-03).
- Модалки, меню, выпадающие списки — готовые примитивы, не самописные (FA11Y-05).

**Ошибки и наблюдаемость**
- Error Boundary на корне и маршрутах: белого экрана нет (FOBS-01).
- Ошибки — в сбор ошибок с релизом и source maps; пустых `catch` нет (FOBS-02, FOBS-03).
- Сообщение об ошибке показывает `request_id` (FOBS-05). `console.log` — не в проде (FOBS-04).

**Тесты и типы**
- `model/` — модульные тесты; компоненты — Testing Library по ролям; сеть — MSW (FTST-01…FTST-03).
- Главные пути (вход, создание, оплата) — e2e на Playwright с axe (FTST-04).
- Нет `any`: `unknown` и сужение; `@ts-expect-error` с причиной, не `@ts-ignore` (FTS-02, FTS-03).
- Данные извне (API, storage, URL, postMessage) — из типизированного клиента или через схему (FTS-04).

## Антипаттерны

- ❌ `useEffect(() => { fetch(...) })`; данные сервера в `useState`/сторе
- ❌ Бизнес-условия в JSX; глубокий импорт чужой фичи; `shared` знает о фиче
- ❌ `fetch`/`axios` мимо клиента; ручные типы ответа API
- ❌ Токен в `localStorage`; секрет в `VITE_*`; `dangerouslySetInnerHTML` с данными
- ❌ `any`, `@ts-ignore`, `eslint-disable` без причины
- ❌ `div` с `onClick`; картинка без `alt`; самописная модалка
- ❌ Список без пагинации; двойной сабмит платежа; `key={index}`
- ❌ Пустой `catch`; белый экран вместо ошибки

## Перед коммитом

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm knip
```

Затронуты архитектура, API, формы, авторизация или зависимости —
`frontend-review` по изменениям.
