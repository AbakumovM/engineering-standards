# Правила разработки

Общие правила для всех проектов. Правила области — в её ядре, оно
подключается рядом с этим файлом: бэкенд (Python) — `backend.md`,
фронтенд (TypeScript, React) — `frontend.md`. Ядро области не загружено, а
работа в ней — прочитать его из каталога engineering-standards.

## Уровни и отклонения

- У каждого правила номер (`TX-02`, `FAPI-04`) и уровень: **обязательно**
  (нарушение — дефект) или **по умолчанию** (разумный выбор).
- Проект отступает только записью в своём `AGENTS.md` / `CLAUDE.md`, раздел
  «Отклонения от общих правил»: `- TX-02: <где и почему>`. Незаписанное
  отступление — нарушение. В коде: `# arch-ignore[ID]: причина`
  (Python) или `// arch-ignore[ID]: причина` (TypeScript).
- Обязательное правило без согласия пользователя не нарушать: объяснить,
  предложить запись в «Отклонения», ждать решения.

## Когда звать скиллы

| Область | До работы | После фичи, перед коммитом/MR, «проверь код» |
|---|---|---|
| Бэкенд | `backend-guide` | `backend-review` |
| Фронтенд | `frontend-guide` | `frontend-review` |

Сначала прочитать нужный раздел руководства, потом писать код. Правила и
пример в самом проекте (аккуратный домен/фича-образец) важнее привычки.

## Общее для обеих областей

- Стек по умолчанию — в ядре области; замена пункта — отклонение.
- Файл появляется вместе с содержимым; нет `common/`, `utils/`, `helpers/` —
  техника лежит по назначению.
- Контракт фронта и бэка — OpenAPI бэкенда: клиент фронта генерируется из
  него, ошибки — problem+json, списки — курсор, создающий `POST` —
  `Idempotency-Key`, в ответе — `request_id`.
- Права проверяет сервер; скрытая кнопка — удобство, не защита.
- Секреты — не в коде, не в логах, не в бандле фронта.
- Правило — чистая функция с тестом; тест, прошедший с первого раза, проверить порчей кода.
- Исключение не глотается: обработать (показать, повторить, пропустить с
  предупреждением в лог) или пробросить.
