# Бэкенд: Python-сервисы

Номера (`DEP-04`) ведут в `backend-guide/catalog.md`: там причина, способ
проверки и исключения.

**`backend-guide`** — перед тем как создать проект, домен, сценарий, порт,
адаптер, эндпоинт, миграцию, фоновую задачу, интеграцию с внешним API или
переносить старый код. **`backend-review`** — после фичи, перед коммитом/MR,
по просьбе «проверь архитектуру / код / безопасность».

## Стек по умолчанию

Python 3.12+, uv, ruff, mypy strict, pytest + pytest-asyncio; FastAPI;
Dishka (DI); SQLAlchemy async + Alembic; FastStream (брокер); pydantic-settings;
import-linter (границы). Замена любого пункта — отклонение в проекте.

## Структура

```
src/<пакет>/
  <домен>/
    domain/          # правила, модели, события, исключения — без внешних зависимостей
    application/     # сценарии (Interactor, Service), dto.py (Info), config.py,
                     # interfaces/ — Protocol: Gateway (запись), View (чтение), внешние сервисы
    adapters/        # реализации портов: SQL, клиенты внешних API
    controllers/     # HTTP, бот, обработчики брокера, CLI: вход → сценарий → ответ
    ioc.py           # провайдеры Dishka
    public.py        # единственное, что импортируют соседи
  infrastructure/    # БД, единица работы, http-клиенты, настройки, брокер
  <процесс>_main.py  # точки сборки: контейнер, роутеры, фоновые задачи
```

- Сначала домены, внутри слои (STR-01). Слои есть у всех доменов, тонкие допустимы (STR-02).
- Файл появляется вместе с содержимым: без пустых `events.py`, `v1/` и т.п. (STR-03).
- Нет `common/`, `utils/`, `helpers/`: техника — `infrastructure/<назначение>/` (STR-04).
- Модульный монолит; отдельный сервис — только по проверенной границе (STR-06).

## Главные правила

**Зависимости**
- Направлены внутрь: `domain` ← `application` ← `adapters`, `controllers` (DEP-01).
- `domain` не импортирует ничего, кроме стандартной библиотеки (DEP-02).
- `application` получает зависимости портами, настройки — значением `{Что}Config` (DEP-03).
- Сосед — только через `<домен>.public`; таблица принадлежит одному домену,
  на чужое — по id (DEP-04, DEP-05).
- Границы проверяет import-linter в CI; исключение — с комментарием «когда снимется» (DEP-06).

**Домен и сценарии**
- Правило (деньги, сроки, доступ, «можно ли») — чистая функция в `domain/`
  с тестами; «можно ли» возвращает причину отказа (DOM-01, DOM-02).
- Доменные исключения `{Что}{Проблема}Error`, не `ValueError` (DOM-03).
- Interactor: один агрегат, один Gateway; возвращает frozen `{Entity}Info` (APP-01, APP-02).
- Данные для решения читает Gateway в транзакции; View — для ответа, в
  контроллере и сервисе; свой View в Interactor не инжектируется (APP-03).
- Service — когда одна транзакция пишет несколько доменов или процесс
  переиспользуется несколькими входами (APP-04). Не «на вырост» (APP-07).
- Сценарий не вызывает сценарий соседа; нужен посередине — две фазы (APP-05).
- Внешний сервис — порт в `application/interfaces/`, адаптер в `adapters/` (APP-06).

**Транзакции**
- Коммит явный, в конце метода сценария; исход без записи — `rollback()` (TX-01).
- Внутри транзакции нет HTTP, очередей, писем (TX-02). Порядок шагов —
  такой, чтобы сбой между ними оставлял исправимое состояние (TX-03).
- Коммитит владелец транзакции; порт соседа в чужой транзакции не коммитит (TX-04).
- Ожидаемый конфликт уникальности — savepoint + доменное исключение (TX-07).
- События наружу — outbox в той же транзакции (TX-09). Обработчики вебхуков
  и событий идемпотентны: «уже исполнено», а не «уже получено» (TX-10).

**Контроллеры и адаптеры**
- Контроллер: разобрать → вызвать → ответить; ни одного бизнес-`if` (CTL-01).
- Внешний клиент — один на процесс, всегда с таймаутами (ADP-01).
- Синхронное и блокирующее — не в event loop (ADP-03).
- Адаптер под протокол отдаёт функция провайдера с типом-протоколом, не `provides=` (DI-02).
- Схему создают только миграции (DB-02).

**API и безопасность**
- Явные схемы входа/выхода, `extra="forbid"`, потолки длин и размеров (API-01, API-07).
- Один формат ошибок (problem+json), без стектрейсов (API-02).
- Любой список — с `limit` и курсором с первого дня (API-04).
- Создающий/платёжный `POST` — с `Idempotency-Key` (API-05). Контракт не ломать (API-06).
- Сценарий по id проверяет право субъекта на объект; нет прав — 404 (SEC-01).
  Админское — отдельный роутер с ролью (SEC-02).
- Только параметризованный SQL (SEC-05); секреты — `SecretStr` из окружения (SEC-04);
  подпись вебхука — по сырому телу, `compare_digest` (SEC-06).

**Нагрузка и надёжность**
- Нет запросов в цикле (PERF-01); индекс под каждый новый запрос по растущей таблице (PERF-02).
- `statement_timeout`, бюджет соединений посчитан (PERF-03, PERF-04).
- Параллельность к внешним API ограничена; долгое — в очередь, не в запрос (PERF-05, PERF-06).
- Повторы — только идемпотентного, с джиттером и потолком, на одном уровне (REL-02).
- liveness без зависимостей, readiness проверяет БД (REL-04); мягкая остановка (REL-05).
- Фоновый цикл переживает сбой итерации (REL-06).

**Наблюдаемость и данные**
- Структурированные логи с `request_id`; без паролей, токенов, тел запросов (OBS-01…OBS-03).
- Исключение не глотается и логируется один раз на границе (OBS-04).
- Время — `datetime.now(UTC)`, `timestamptz`; деньги — не `float` (OPS-01, OPS-02).
- Миграции без простоя: expand → contract, `lock_timeout`, индекс `CONCURRENTLY` (OPS-04, OPS-05).

**Тесты и перенос**
- Правила домена — модульные тесты; адаптеры — на настоящей тестовой БД (TST-01, TST-02).
- Тест, прошедший с первого раза, проверить порчей кода (TST-04).
- Старый код: новое — только в новой структуре; сначала тесты на текущее
  поведение; перенос поведение не меняет, баг — отдельно (LEG-01…LEG-03).

**Типы**
- mypy strict для нового кода; `type: ignore[код]  # почему` (TYP-01). Весь I/O — async.

## Именование

| Что | Шаблон |
|---|---|
| Сценарий / сервис | `{Entity}Interactor` / `{Workflow}Service` |
| Порты | `{Entity}Gateway` (запись), `{Entity}View` (чтение) |
| Реализация порта | `{Технология}{Порт}`: `PgAssetGateway` |
| Результат / план | `{Entity}Info` / `{Что}Plan` — frozen dataclass |
| Команда / запрос | `CreateAsset` / `GetAssetList` |
| Событие | прошедшее время: `AssetCreated` |
| Исключение | `AssetNotFoundError` |
| Провайдер | `{Домен}{Слой}Provider` |

## Антипаттерны

- ❌ Бизнес-логика в контроллере; `commit()` в контроллере или адаптере
- ❌ Несколько Gateway в Interactor; сценарий соседа внутри сценария
- ❌ Импорт внутренностей чужого домена; чтение чужих таблиц
- ❌ Возврат доменной модели или строки ORM из сценария
- ❌ HTTP/брокер/почта внутри открытой транзакции; `publish()` без outbox
- ❌ Клиент (httpx, сессия) на каждый запрос; запрос без таймаута
- ❌ `common/` как свалка; пустые файлы «на будущее»
- ❌ `type: ignore` без кода и комментария; синхронный I/O
- ❌ Список без пагинации; объект по id без проверки владельца
- ❌ `except Exception: pass`; секреты и тела запросов в логах
- ❌ `float` для денег; `datetime.now()` без зоны

## Перед коммитом

```bash
uv run ruff check --fix && uv run ruff format && uv run lint-imports && uv run mypy && uv run pytest
```

Затронуты архитектура, API, транзакции, миграции или внешние вызовы —
`backend-review` по изменениям.
